# STM32 FreeRTOS Ethernet Demo

This project demonstrates the integration of XCPlite (XCP on Ethernet) on a STM32H753 runing FreeRTOS.  
It uses the NXPCubeMX tools.  
The example configuration is for a STM NUCLEO-H753 board.    

For full documentation of XCPlite on microcontrollers with FreeRTOS, first look at the README.md in the fully public domain platformio toolchain example in example folder esp32_freertos_demo.


The folder stm32_freertos_demo includes only additional files and user modified CubeMX generated files.
The content is generated from the Vector toolchain specific repo folder with  
```bash
.\publish.ps1 -Destination .\stm32_freertosdemo_cubemx
```


If you are a user of the Vector internal toolchain and framework, see INSTALL.MD for instructions how to install the framwork.

   - Returning 0 lets LwIP continue normal ping reply handling.


## Basic XCP test

Execute a basic XCP connection test:

```bash
xcpclient --udp --dest-addr 192.168.0.207
```

The upload A2L file error message can be ignored, as the FreeRTOS implementation does not support on-target A2L generation and A2L upload.


Execute a quick test measurement without an A2L file:

```bash
xcpclient --udp --dest-addr 192.168.0.207 --elf build/Debug/STM32H753EthDemo.elf --elf-unit-filter xcp_demo --mea global_counter --verbose 2

```

You should see the counter variable incrementing every 2ms.  


## Generate A2L file

Examples:

```bash
# Create am A2L file template with events, memory_segments, epk, and all requireds communication settings  
xcpclient --offline --elf build/Debug/STM32H753EthDemo.elf  --elf-unit-filter xcp_demo --a2l stm32_freertos_demo.a2l --create-a2l-template

# To create the A2l with correct IP add  
xcpclient --offline --udp --dest-addr 192.168.0.207 ....

# Automatically add all possible measurement variables and calibration parameters in calibration parameter segment 
xcpclient --offline --udp --dest-addr 192.168.0.207 --elf build/Debug/STM32H753EthDemo.elf --a2l stm32_freertos_demo.a2l --elf-unit-filter xcp_demo

```

See esp32_freertos_demo for more details.  


## Configuration 



Configuration changes compared to default CubeMX generated code:

- assert_failed modified
- MPU_Config: the default MPU configuration generated by CubeMX is not compatible with the LwIP stack, so we replace it with a custom one that allows unaligned accesses and sets the Ethernet DMA buffers region as cacheable.
- SystemClock_Config: the default clock configuration generated by CubeMX is modified to set the AHB clock to 200MHz (instead of 100MHz) to provide enough bandwidth for the Ethernet peripheral at 100Mbps.
- LwIP options in lwipopts.h: we set the options to values compatible with the default CubeMX configuration for LwIP, and also enable some options that are required for the LwIP port on H7 (e.g. LWIP_NETCONN_SEM_PER_THREAD, LWIP_NETCONN_FULLDUPLEX, LWIP_SO_RCVTIMEO) or that improve performance (e.g. LWIP_NETIF_TX_SINGLE_PBUF, CHECKSUM_BY_HARDWARE).
- The LwIP heap is relocated to 0x30004C00 to avoid overlapping with the RX pool (memp_memory_RX_POOL_base) that occupies 0x300000c0..0x30004A5F in RAM_D2.
- The main function initializes the HAL, the system clock, the peripherals, and starts the FreeRTOS scheduler. The actual application code should be added in the FreeRTOS tasks that you create (e.g. in freertos.c).


Note: the code in all files except xcp_demo is generated by STM32CubeMX.  
You can modify it as needed. However, be aware that if you regenerate the code from CubeMX, your modifications may be lost. 
To prevent this, you can use the "USER CODE BEGIN" and "USER CODE END" sections to add your code, as these sections are preserved during code regeneration.  

User code modifications are in:

- **`Core/Inc/FreeRTOSConfig.h`**  
  Added `configASSERT(x)` implementation: disables interrupts and halts in an infinite loop on assertion failure, making assertion faults visible to a debugger without returning.  
  Added `configNUM_THREAD_LOCAL_STORAGE_POINTERS 1` to provide the FreeRTOS thread-local storage (TLS) slot required by the per-thread LwIP netconn semaphore (`LWIP_NETCONN_SEM_PER_THREAD`).

- **`Core/Src/freertos.c`**  
  Main application task (`tskFctDefault`): initializes LwIP, assigns a static IP address (`IP_ADDRESS`/`IP_NETMASK`/`IP_GW`), registers a raw-socket ICMP ping listener, initializes the XCP demo (`xcp_demo_init()`), and blinks the green LED.  
  Added `ping_recv_callback` which detects ICMP Echo Requests, toggles the red LED, and logs the ping source via `printf`. Returns 0 so LwIP still sends the ping reply normally.  
  Added a stub `vApplicationStackOverflowHook` for stack-overflow detection.

- **`Core/Src/main.c`**  
  Clears `SCB_CCR_UNALIGN_TRP_Msk` before `HAL_Init()` to suppress HardFaults on unaligned accesses (newlib `crt0` sets this bit; LwIP and the XCP stack require unaligned access on Normal memory).  
  Custom `MPU_Config()` replaces the CubeMX default: region 0 covers the full 4 GB address space as strongly-ordered/non-cacheable for peripheral safety; region 1 maps 256 KB at `0x30000000` (RAM_D2, where Ethernet DMA buffers reside) as TEX=L1/cacheable; region 2 maps 512 KB at `0x24000000` (AXI SRAM) as cacheable + bufferable.  
  `SystemClock_Config` sets `AHBCLKDivider = RCC_HCLK_DIV2`, raising HCLK from the CubeMX default of 100 MHz to 200 MHz to provide sufficient memory bandwidth for 100 Mbps Ethernet.  
  `Error_Handler()` calls `__disable_irq()` before the infinite loop so that a debugger can break in and inspect the full call stack without being disturbed by pending interrupts.

- **`Core/Src/stm32h7xx_it.c`**  
  Extended `HardFault_Handler()` with volatile captures of HFSR, CFSR, MMFAR, BFAR, AFSR, and the faulting PC (from MSP) to facilitate post-mortem debugging in a debugger.  
  Added `ETH_IRQHandler()` to forward the Ethernet global interrupt to `HAL_ETH_IRQHandler()` (the Ethernet IRQ is not routed through the CMSIS-RTOS layer).

- **`Core/Src/usart.c`**  
  Baud rate changed from 115200 to 250000 baud for faster serial trace output.  
  Added `__io_putchar()` to redirect `printf()` to USART3, which is connected to the ST-LINK virtual COM port.

- **`LWIP/Target/ethernetif.c`**  
  `INTERFACE_THREAD_STACK_SIZE` increased from the CubeMX default of 512 to 1024 bytes to accommodate the `ethernetif_input` → `HAL_ETH_ReadData` → `tcpip_input` call chain.  
  Ethernet interface thread priority set to `osPriorityRealtime` to ensure timely packet reception under load.

- **`LWIP/Target/lwipopts.h`**  
  `LWIP_RAW 1`: enables the raw socket API, required by the ICMP ping listener in `freertos.c`.  
  `LWIP_NETIF_TX_SINGLE_PBUF 1`: forces LwIP to copy TX data into a single pbuf before DMA, necessary because XCPlite may pass stack or heap buffers that are not accessible by the Ethernet DMA in all memory regions.  
  `LWIP_RAM_HEAP_POINTER` relocated from `0x30004000` to `0x30004C00`: the RX pool (`memp_memory_RX_POOL_base`) occupies `0x300000C0`–`0x30004A5F` in RAM_D2, so the LwIP heap must start after it to avoid overlap.  
  Added `LWIP_NETCONN_THREAD_SEM_TLS_INDEX` and the corresponding `LWIP_NETCONN_THREAD_SEM_GET/ALLOC/FREE` macros to integrate the per-thread netconn semaphore with the FreeRTOS TLS slot.

- **`STM32H753XX_FLASH_changed.ld`**  
  Stack relocated from DTCMRAM to AXI SRAM (`RAM` at `0x24000000`): DTCMRAM is not accessible by the Ethernet DMA.  
  Added linker sections `.RxDescripSection`, `.TxDescripSection`, and `.Rx_PoolSection` mapped to `RAM_D2` (`0x30000000`) to place Ethernet DMA descriptors and the LwIP RX buffer pool in the memory region accessible by the Ethernet DMA peripheral.  
  Added `xcp_cals` and `xcp_evts` sections in FLASH to keep XCPlite calibration-parameter and event-descriptor objects alive under `--gc-sections`.





1. Under heavy load, XCPlite may transmit multiple UDP packets:

It is in the users responsibility to provide enough resources:

For example in lwipopts.h:

```C
#define TCPIP_MBOX_SIZE             20
```


2. UDP transmit buffer Memory 

XCPlite uses 2 different storage areas for buffer pointers given to lwip_sendto,
stack (for XCP commend responses and event messages) and heap (for queued measurement data, allocated with aligned_alloc in queue.c)
In both cases, lifetime of the memory may be assumed valif only until lwip_sendto returns!

Note:
This is default behavaviour and may be optimzed. XCPlite has an option to queue all packets. The lifetime of data consumed from the queue can be controlled explicitly, as well as the kind of memory allocated for the queue.

For the default behaviour, lwip has to copy the transmitted packets, because DMA is not possible in all memory regions:

In lwipopts.h:

```C
#define  LWIP_NETIF_TX_SINGLE_PBUF
```
